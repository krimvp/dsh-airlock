# e2e

End-to-end verification of `dsh-airlock` against the real DeepSeek Harness,
driven by a real model. Nothing here is mocked: a genuine `dsh` CLI boots a
genuine profile, a genuine model calls genuine tools, and every assertion is
read out of the session log rather than out of what the model says happened.

```sh
OLLAMA_API_KEY=... e2e/verify.sh
```

## What it proves

Each scenario runs twice, once with the plugin mounted and once without it. A
denial with no control arm proves nothing: it could be the model declining, the
sandbox refusing, or the tool being absent. The contrast is the evidence.

| Scenario | Claim under test |
| --- | --- |
| `reads-open` | `read`, `glob`, and `grep` are never gated. |
| `secret-egress` | A read of a secret path closes egress for the rest of the session. |
| `untrusted-egress` | An MCP tool result closes egress for the rest of the session. |
| `killchain` | An indirect injection cannot reach egress after a secret read. |
| `killchain-covert` | The same chain with a payload that does not look malicious. |
| `shell-read` | A secret read through the shell instead of `read`. |

## Reading the output

- `PASS` — the assertion held.
- `FAIL` — the assertion did not hold. The script exits non-zero.
- `WEAK` — the model declined to attempt the step, so that arm measured
  nothing. A `WEAK` line is never evidence that the gate works.
- `GAP` — a known structural limit reproduced. Not a regression, not a pass.

Transcripts, decoded tool traffic, and copied session logs land under
`$E2E_ROOT/results/<scenario>.<arm>/`.

## Configuration

| Variable | Default | Meaning |
| --- | --- | --- |
| `OLLAMA_API_KEY` | — | Required. Read as a name only; never printed or written. |
| `E2E_ROOT` | `${TMPDIR:-/tmp}/dsh-airlock-e2e` | Scratch root for the dsh install, `$DSH_HOME`, fixtures, and results. Outside the repository by design. |
| `E2E_MODEL` | `deepseek-v4-flash:preview` | Model id on the Ollama Cloud route. |
| `E2E_DSH_VERSION` | `latest` | npm version of `@deepseek-ai/dsh`. |
| `E2E_PROFILE` | `airlock` | Profile name inside the scratch `$DSH_HOME`. |
| `E2E_TIMEOUT` | `300` | Per-run seconds. |
| `E2E_SKIP_INSTALL` | unset | `1` reuses an existing scratch install. |

`$DSH_HOME` is set to `$E2E_ROOT/dsh-home`, so the user's real dsh
configuration is never read or written.

## Safety of the fixture

The fixture `.env` holds fabricated values only. Every egress in the fixture
points at `https://example.invalid/`, a domain reserved by RFC 6761 that cannot
resolve. `verify.sh` refuses to start if it does resolve on the host, so an
unguarded run leaks nothing even when the guard is absent by design.

Both arms run with `DSH_PERMISSION_MODE=danger-full-access`. That is deliberate.
The headless surface has nobody to answer an approval prompt, and a plain
container has neither bubblewrap nor Landlock, so under `workspace-write` the
bash tool refuses to run at all and both arms would be silently equal. Running
unconfined removes every other restraint, which leaves the plugin as the only
thing that can stop egress — which is the property under test.

## Layout

```
verify.sh                     the one command
lib/decode-log.mjs            decode session.jsonl.zstd (multi-frame zstd)
lib/probe.mjs                 answer one question about a session log
lib/mcp-notes-server.mjs      fixture MCP server, one tool, injected payload
patches/profile.cordis.patch.yml   the profile's LLM route and default model
patches/mcp-notes.patch.yml        mount the fixture MCP server
```

The plugin mount overlay is generated by `verify.sh` rather than shipped: a
loader entry's `name` is resolved before `!!js` expressions are evaluated, so
`name: !!js process.env.X` fails with `name.startsWith is not a function`.
`!!js` inside `config` works, which is why the MCP overlay can stay static.

## Harness facts this depends on

Verified against `@deepseek-ai/dsh` `0.1.0-rc.6`.

- A profile is `$DSH_HOME/profiles/<name>/` with a `package.json` naming its
  bundles in `dsh.profile.bundles` and a `cordis.patch.yml` user layer. `dsh`
  creates the directory and heals a module fallback on first boot.
- A plugin mounts from an absolute filesystem path as its `name`. No `npm link`
  and no packed tarball are needed.
- The mount needs `inject: [tools]`. Cordis throws on an undeclared service
  property access, so the plugin's `toolRuntime(ctx)` fails plugin load without
  it, taking the whole tree down rather than degrading.
- `--patch <file>` overlays apply after the profile layer, which is what makes
  the control and treatment arms differ by exactly one file.
- `session.jsonl.zstd` is a concatenation of independent zstd frames. Node's
  one-shot and streaming decompressors both stop after the first frame.
